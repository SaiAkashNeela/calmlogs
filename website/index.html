Docker Compose Stack

Drop 1 service into your compose file.

CalmLogs automatically parses container tags (like postgres-1 | ... and redis-1 | ...) and registers each service dynamically in the dashboard.

  • No need to build custom Docker images or install agents
  • Filter by specific Docker network or log the entire file
  • Cleans container prefixes so log messages stay readable
docker-compose.yml 
services:
  # Add to your compose file:
  calmlogs:
    image: node:alpine
    container_name: calmlogs-forwarder
    restart: unless-stopped
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock
    command: >
      sh -c "apk add --no-cache docker-cli docker-cli-compose &&
      docker compose logs -f --no-color | npx -y calmlogs --project 'prod-stack'"

Frequently Asked Questions

Everything you need to know about CalmLogs architecture and open-source licensing.

Is CalmLogs really free and open source?

Yes. CalmLogs is released under the MIT license. You can run it locally, self-host it on your own Cloudflare account for virtually zero cost, or deploy it in your own private cloud.

How does it auto-detect Docker Compose services?

The CLI parses standard compose log streams (e.g. api-1 | ...). It extracts the service name, strips the container instance suffix, and routes logs dynamically into separate services.

What happens if my internet or connection drops?

The CLI tool operates with non-blocking buffers and never crashes your primary application process. If an ingestion endpoint fails, your server keeps running smoothly without disruption.

Can I use it with Python, Go, Rust, or Java?

Yes! Any program that logs to stdout/stderr can be piped into npx calmlogs, or can use our native HTTP batch ingestion endpoint POST /v1/logs.

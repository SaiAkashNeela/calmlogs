CalmLogs Documentation

CalmLogs is an open-source, edge-native distributed logging system built for developers. Instead of forcing you to install heavy host daemons or rewrite logging calls across 40 different microservice repositories, CalmLogs lets you pipe stdout directly into a high-speed real-time dashboard.

The Core Philosophy: If your program writes to stdout or outputs JSON lines, CalmLogs can ingest, index, and live-tail it with zero code modifications.

Why CalmLogs?

  • No SDK Bloat: Works seamlessly with standard Unix pipes or container stdout streams.
  • Docker Compose Native: Drop 1 forwarder service into your compose file to automatically map all containers into separate service tabs.
  • $0 Cloudflare Free Tier: Designed to run completely free within Cloudflare Workers, R2, and D1 SQLite permanent free quotas.
  • Edge WebSocket Tail: Cloudflare Durable Objects broadcast logs globally in real time with sub-100ms latency.

30-Second Quickstart

You can stream logs from any command into CalmLogs immediately using npx without installing anything globally:

1. Unix Pipe (Simplest)

Terminal Pipe 
# Stream logs from your existing start command
npm start | npx calmlogs --project "my-backend" --service "api"

2. Sub-Process Runner

Alternatively, use the run sub-command to launch your server as a child process:

Process Runner 
npx calmlogs run --project "core" --service "api" -- python -u app.py

CLI Reference (calmlogs)

The calmlogs command-line executable acts as an ultra-lightweight, non-blocking forwarder.

Flag Short Description Default Value
--project <name> -p Project name in CalmLogs Auto-detected from current folder or default
--service <name> -s Service name in CalmLogs Auto-detected from package.json or app
--key <token> -k Ingestion API key (cl_live_...) Optional / CALMLOGS_KEY
--endpoint <url> -e CalmLogs platform endpoint URL http://localhost:3000
--network <net> -n Docker network metadata filter None (logs all services)

Environment Variables

All flags can be configured via environment variables:

  • CALMLOGS_PROJECT: Default project name
  • CALMLOGS_SERVICE: Default service name
  • CALMLOGS_KEY: Default ingestion API key
  • CALMLOGS_ENDPOINT: Ingestion platform endpoint

Auto-Resolution Engine

What happens if you accidentally run my-server | npx calmlogs without supplying --project or --service? CalmLogs will never reject or drop your logs.

  1. API Key Lookup: If an API key is provided, the backend queries the database by the key's SHA-256 hash to automatically resolve the exact project and service that owns that key.
  2. Local Environment Auto-Detection: The CLI inspects package.json in the current folder for the service name, and uses the current working directory name for the project.
  3. Platform Fallback: If no metadata is provided, the platform automatically routes the logs to project default and service app, creating them on the fly.

Docker Compose Sidecar Service

In a multi-container Docker Compose stack, you don't need to install anything inside your individual containers. Simply add the calmlogs sidecar service to your docker-compose.yml:

docker-compose.yml 
services:
  # Add this forwarder service to your docker-compose.yml:
  calmlogs:
    image: node:alpine
    container_name: calmlogs-forwarder
    restart: unless-stopped
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock
    # networks: [backend_net]  # Optional: limit to specific network
    command: >
      sh -c "apk add --no-cache docker-cli docker-cli-compose &&
      docker compose logs -f --no-color | npx -y calmlogs --project 'prod-stack' --key 'cl_live_...'"

How Container Separation Works

Docker Compose outputs lines prefixed with container names:

Docker Compose Output
api-1      | {"level":"info","message":"User logged in"}
postgres-1 | 2026-09-11 22:20:00 [LOG] database system is ready
redis_1    | Ready to accept connections

CalmLogs dynamically parses the container prefix, strips the instance tag (-1, _1), routes each line into its own service tab in your dashboard (api, postgres, redis), and strips the prefix from the message for crystal-clear readability.

Language & Framework Guides

Node.js & Bun

Compatible with standard Pino, Winston, Bun, and console logging:

Node.js Pipe
node index.js | npx calmlogs --project "web" --service "backend"

Python (FastAPI, Loguru, Django)

Use the -u unbuffered flag to stream logs in real time:

Python Pipe
python -u main.py | npx calmlogs --project "ml-service" --service "worker"

Go & Rust

Go & Rust
# Go
go run . | npx calmlogs --project "payments" --service "processor"

# Rust
cargo run --release | npx calmlogs --project "trading" --service "engine"

HTTP Ingestion API

If you prefer sending logs directly over HTTP, send a single JSON event or an array of up to 1,000 logs to POST /v1/logs:

POST /v1/logs
curl -X POST https://calmlogs.com/v1/logs \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer cl_live_your_key" \
  -d '[
    {
      "project": "ecommerce",
      "service": "checkout",
      "level": "info",
      "message": "Cart processed successfully",
      "metadata": { "orderId": "ord_8819", "total": 128.50 }
    }
  ]'

Direct Workspace Invitations

Inviting teammates to your CalmLogs organization requires zero email server configuration.

  • Direct Link Generation: When an admin invites a member, CalmLogs generates an instant shareable link: https://calmlogs.com/?invitation_id=<id>.
  • Sign In / Sign Up Flow: The recipient opens the link and signs in with their Google account.
  • Review & Decision Modal: Once authenticated, the user is presented with a clear prompt displaying the workspace name and invited role with Accept and Decline options.

Security & Hardening (100/100 Audit)

CalmLogs underwent a comprehensive defensive cyber security audit adhering to OWASP Top 10 standards. Review the formal audit report at docs/security-audit.md.

  • SHA-256 Key Hashing: Plaintext API keys are never stored in the database; only one-way SHA-256 digests exist in SQLite.
  • Path Sanitization: Storage paths sanitize all project and service names with /[^a-zA-Z0-9_\-\.]/g, neutralizing path traversal and delimiter injection.
  • Payload & Memory Clamping: Ingestion bodies are restricted to 5MB max, batches to 1,000 logs, and individual messages are clamped to 64KB to eliminate memory exhaustion vectors.

Or deploy manually via CLI in 4 simple commands:

Bash
# 1. Clone repository
git clone https://github.com/SaiAkashNeela/calmlogs.git

# 2. Install dependencies & build
bun install
bun run build

npx wrangler d1 migrations apply DB --remote

npx wrangler deploy

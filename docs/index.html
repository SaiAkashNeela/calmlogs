CalmLogs Documentation

CalmLogs is a minimalist, edge-native distributed logging system built for developers. Instead of forcing you to install heavy agent daemons or rewrite logging calls in your code, CalmLogs lets you pipe stdout directly into a high-speed real-time dashboard.

Key Philosophy: Zero code modifications. If it outputs to stdout or writes JSON lines, CalmLogs can ingest, index, and live-tail it.

Quickstart in 30 Seconds

Pipe any command directly into calmlogs using npx:

Terminal Pipe 
npm start | npx calmlogs --project "my-backend" --service "api"

Or use the sub-command runner to execute your process as a child:

Process Runner 
npx calmlogs run --project "my-backend" --service "api" -- python main.py

CLI Reference (calmlogs)

The calmlogs CLI is packaged directly inside the repository and can be run via npx calmlogs or installed globally.

Command Line Flags

Flag Short Description Default
--project <name> -p Project name in CalmLogs Auto-detected from directory / default
--service <name> -s Service name in CalmLogs Auto-detected from package.json / app
--key <token> -k Ingestion API Key (cl_live_...) Optional / CALMLOGS_KEY
--endpoint <url> -e CalmLogs platform endpoint URL http://localhost:3000
--network <net> -n Docker network metadata filter None

Environment Variables

You can configure the CLI permanently using environment variables in your .env or CI environment:

  • CALMLOGS_PROJECT: Project name
  • CALMLOGS_SERVICE: Service name
  • CALMLOGS_KEY: Ingestion API secret key
  • CALMLOGS_ENDPOINT: CalmLogs ingestion host

Auto-Resolution Engine

What happens if you accidentally run my-app | npx calmlogs without passing --project or --service? CalmLogs will never reject or drop your logs.

  1. API Key Lookup: If an API key is provided, the backend hashes the token and immediately resolves the exact project and service associated with that key in the database.
  2. Local Environment Auto-Detection: The CLI inspects package.json in the current folder for the service name, and uses the current working folder name for the project.
  3. Platform Fallbacks: If all metadata is absent, the backend routes to project default and service app and auto-creates them on the fly.

Docker Compose Sidecar

CalmLogs features native support for multi-container Docker Compose networks. Simply add the calmlogs forwarder service to your docker-compose.yml:

docker-compose.yml 
services:
  # Add this forwarder service to your docker-compose.yml:
  calmlogs:
    image: node:alpine
    container_name: calmlogs-forwarder
    restart: unless-stopped
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock
    # networks: [backend_net]  # Optional: limit to specific network
    command: >
      sh -c "apk add --no-cache docker-cli docker-cli-compose &&
      docker compose logs -f --no-color | npx -y calmlogs --project 'prod-stack' --key 'cl_live_...'"

How It Separates Containers into Services

Docker Compose outputs lines like api-1 | ... and postgres-1 | .... CalmLogs automatically strips the container index suffix (-1), extracts the service name (api, postgres), and routes each line to its own dedicated service in the dashboard.

Language Guides

Node.js & Bun

Any standard logger (Pino, Winston, Bun) works automatically:

Node.js Pipe
node dist/index.js | npx calmlogs --project "web" --service "backend"

Python (FastAPI, Loguru, Django)

Pipe standard stdout or unbuffered python output:

Python Pipe
python -u app.py | npx calmlogs --project "ml-service" --service "worker"

Go & Rust

Go / Rust Pipe
# Go
go run main.go | npx calmlogs --project "finance" --service "ledger"

# Rust
cargo run --release | npx calmlogs --project "finance" --service "engine"

HTTP Ingestion API

Send single logs or batches of up to 1,000 items via HTTP POST:

POST /v1/logs
curl -X POST http://localhost:3000/v1/logs \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer cl_live_your_key" \
  -d '[
    {
      "project": "core",
      "service": "api",
      "level": "info",
      "message": "User checkout completed",
      "metadata": { "orderId": "ord_123", "amount": 49.99 }
    }
  ]'

Edge Architecture

CalmLogs is engineered as a serverless edge system:

  • Cloudflare Worker: Edge router receiving ingestion HTTP requests and managing WebSocket connections across 200+ global data centers.
  • Durable Objects (LogRingBuffer): Acts as the in-memory pub/sub broker per service. Manages live WebSocket subscriptions and client fan-out.
  • Cloudflare R2: S3-compatible cold object storage where flushed log segments are persisted in compressed JSONL format.
  • Cloudflare D1 (SQLite): Relational index tracking projects, services, users, and segment metadata.

Security & API Keys

Security is built-in from the ground up:

  • SHA-256 Key Storage: Ingestion API keys (cl_live_...) are shown exactly once on creation and hashed with SHA-256 before storing in D1 SQLite.
  • Tenant Isolation: Organizations and project members enforce strict boundaries. Read-only members cannot create or delete services.
  • Input Clamping & Sanitization: Batch sizes are strictly capped at 1,000 items, bodies at 5MB, and individual messages at 64KB. Path traversal delimiters in project/service names are stripped.

Self-Hosting Guide

You can deploy CalmLogs to your own Cloudflare account in under 5 minutes:

Deploy
git clone https://github.com/SaiAkashNeela/calmlogs.git
cd calmlogs
bun install
bun run build
npx wrangler d1 migrations apply DB --remote
npx wrangler deploy
